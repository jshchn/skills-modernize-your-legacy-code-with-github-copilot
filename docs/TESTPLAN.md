# COBOL Account Management Test Plan

This plan describes stakeholder-verifiable behavior in the current COBOL
application. Each transaction test that expects an initial balance should start
a fresh application process; the balance is held in working storage and is not
persisted between runs.

Record observed output in **Actual Result** and replace **Not run** in **Status
(Pass/Fail)** with **Pass** or **Fail** after execution. Run the tests in a
controlled environment and restart the program between cases where noted.

| TC-001 | Display the account menu at startup | Application is compiled and not running. | 1. Start the application.<br>2. Observe the first screen. | The application displays the account management menu with options to view balance, credit, debit, and exit, and prompts for a choice from 1 to 4. | — | Not run |  |
| TC-002 | View the initial balance | Start a fresh application process. | 1. Choose `1` (View Balance). | The application displays the current balance as `1000.00` (the numeric display may be zero-padded). | — | Not run | Initial balance comes from `DataProgram` working storage. |
| TC-003 | Credit an account and verify the updated balance | Start a fresh application process; initial balance is `1000.00`. | 1. Choose `2` (Credit Account).<br>2. Enter `125.50`.<br>3. | TC-004 | Debit an amount less than the current balance | Start a fresh application process; initial balance is `1000.00`. | 1. Choose `3` (Debit Account).<br>2. Enter `250.00`.<br>3. | TC-005 | Debit the exact available balance | Start a fresh application process; initial balance is `1000.00`. | 1. Choose `3` (Debit Account).<br>2. Enter `1000.00`.<br>3. Choose `1` (View Balance). | The debit is accepted because the balance is equal to the amount. The new balance is `0.00`. | — | Not run | Verifies the inclusive `balance >= debit amount` boundary. |
| TC-006 | Reject a debit greater than the available balance | Start a fresh application process; initial balance is `1000.00`. | 1. Choose `3` (Debit Account).<br>2. Enter `1000.01`.<br>3. | TC-008 | Handle an invalid menu choice | Start a fresh application process; initial balance is `1000.00`. | 1. Enter `9` at the menu.<br>2. Observe the response and menu loop.<br>3. Choose `1` to view the balance. | The application displays `Invalid choice, please select 1-4.`, displays the menu again, and the balance remains `1000.00`. | — | Not run | Checks invalid selection does not perform an account operation. |
| TC-009 | Exit the application | Application is running and displaying the menu. | 1. Choose `4` (Exit). | The application displays its goodbye message and terminates without requesting a transaction amount or changing the balance. | — | Not run |  |
| TC-010 | Confirm behavior for unsupported or boundary transaction inputs | Business owner is available to define the expected policy. | 1. In separate fresh runs, attempt zero, negative, nonnumeric, and out-of-range amounts for credit and debit.<br>2. Record the observed behavior for each input. | **Requires business decision:** the COBOL code has no explicit amount validation. Agree on the intended acceptance/rejection rules before treating observed COBOL behavior as a business rule. | — | Not run | `AMOUNT` is `PIC 9(6)V99`; runtime behavior for invalid or out-of-range input should not be assumed to be a business rule. The Node.js port currently rejects negative, malformed, and out-of-range amounts, accepts zero, and prevents credits from exceeding `999999.99`; stakeholders should confirm this defensive policy. |
| TC-011 | Confirm balance persistence across application restarts | Application is compiled. | 1. Start a fresh process and credit `10.00`.<br>2. Exit the application.<br>3. Start a new process and view the balance. | The second process starts at `1000.00`; the previous process's balance is not persisted. | — | Not run | Balance is stored in COBOL working storage, not durable storage. Confirm this reset behavior is acceptable to stakeholders. |
